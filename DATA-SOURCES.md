# Откуда берётся статус автомата

## Что я проверил

**Správca zálohového systému (slovenskozalohuje.sk).** Карту делала geoweb.sk,
и точки на ней подгружаются из JSON-файла. Это полный реестр — порядка двух
тысяч odberných miest против пятидесяти из OSM. Но там только адреса и часы,
**статуса машин нет**. Сайт закрыт от автоматического доступа через robots.txt,
поэтому URL этого JSON я тебе дать не могу — найди его сам в DevTools (F12 →
Network → фильтр по XHR, обнови карту) и скорми `scripts/import-file.mjs`.

**TOMRA.** Вот здесь важное. У них есть **TOMRA Status API** — real-time статус
машины, уровень заполнения контейнеров, алерты, вебхуки, OpenAPI-спецификация,
OAuth2, самообслуживание в Developer Portal. То есть ровно те данные, которые
нужны нашему приложению, существуют.

Проблема в области доступа: API адресован владельцам машин — ритейлерам, сетям
и технологическим партнёрам. Это не открытый источник, доступ привязан к
аккаунту, у которого эти автоматы стоят.

Но есть прецедент, который стоит знать: в Австралии TOMRA выкатила потребительское
приложение myTOMRA, где обычный человек видит живой статус ближайшего автомата —
открыт, почти полный, временно недоступен, спящий режим. То есть отдавать статус
конечному пользователю они принципиально готовы, вопрос в договорённости.

**Вывод:** открытого фида статуса не существует. Два реальных пути к живым данным:
партнёрство с TOMRA/Envipco либо кабинет для магазинов, где персонал сам отмечает
поломку. Оба — переговоры, а не код.

## Что делает приложение сейчас

Раз ждать нельзя, статус выводится из того, что доступно:

| Источник | Что даёт | Вес |
|---|---|---|
| Отчёты людей | подтверждённый статус | максимальный, перебивает всё |
| `opening_hours` | открыт ли магазин прямо сейчас | основа оценки |
| Google `business_status` | закрыт временно / навсегда | понижает или обнуляет |
| Базовая доступность 93% | публичная цифра TOMRA по аптайму | априорная вероятность |

Логика в `src/lib/liveness.ts`. Правило простое: магазин открыт, поломок никто
не сообщал → «вероятно работает, 93%». Магазин закрыт → «сейчас недоступен».
Есть свежий отчёт → показываем его и никаких процентов.

## Почему проценты, а не просто зелёный

Оценка и подтверждение выглядят по-разному, и это принципиально. Подтверждённый
статус — сплошная заливка. Оценка — пунктирный контур, приглушённый цвет, процент
рядом и подпись «не подтверждено людьми». Плюс блок «откуда мы это знаем» на
карточке автомата.

Если стереть эту границу и красить всё сплошным зелёным, приложение начнёт врать
в единственном вопросе, ради которого его открывают. Один человек, приехавший
к сломанному автомату с зелёным статусом, больше приложение не откроет.

Часы работы пересчитываются на клиенте при каждой отрисовке и при обновлении
раз в минуту — то есть чаще, чем раз в 15 минут. Крон нужен только для Google
Places (открыт/закрыт навсегда) и для затухания старых отчётов.
