COOP Jednota, у которой одной ~1100 точек, там вообще нет.

## Что использую вместо этого

**Закон.** Дистрибьютор с торговой площадью свыше 300 м² обязан создать и зарегистрировать odberné miesto. То есть каждый супермаркет крупной сети — пункт приёма по определению, это не догадка, а требование законодательства.

**OSM размечает супермаркеты, а не пункты приёма.** Тег `vending=bottle_return` в Словакии почти никто не ставит — отсюда мои 50 точек. Зато `shop=supermarket` с названием, адресом и часами размечен нормально. Ошибка была в том, что я искал не тот тег.

Новый импорт (`npm run import:shops`) берёт из Overpass все супермаркеты, универмаги и cash&carry Словакии, оставляет те, что относятся к сетям с пунктами приёма (Kaufland, Lidl, Tesco, Billa, COOP Jednota, Terno, Kraj, Fresh, CBA, Metro, Milk-Agro), и дедуплицирует по радиусу 70 м.

**Правило без исключений: точка без названия не попадает в базу.** Скрипт их отбрасывает и печатает счётчик. Плюс защита на уровне БД — колонка `quality`, и `machines_near` отдаёт только `quality >= 1`. Даже если заглушка просочится, пользователь её не увидит. Никаких «Odberné miesto» больше не будет ни при каком раскладе.

## Порядок запуска

```powershell
# 1. миграцию 0004_real_stores.sql — в SQL Editor
# 2. импорт настоящих магазинов
npm run import:shops
# 3. дозаполнить улицы там, где в OSM их нет
npm run geocode
```

`import:shops` печатает разбивку по сетям и сколько точек уже с улицей. Это твой первый честный отчёт о качестве данных.

## Дальше по приоритету

**1. Официальный реестр SZS.** Это единственный источник истины: там ровно те точки, что зарегистрированы, включая мелкие магазины, добровольно вошедшие в систему, которых по закону в выборке нет. Напиши в Správca zálohového systému — запроси фид или разрешение на использование карты. Аргумент прямой: вы направляете людей к нашим точкам и снижаете нагрузку на вашу горячую линию. Отказ тоже результат — будешь знать условия.

**2. Проверка ногами.** Возьми 20 точек в Братиславе и сверь: существует ли магазин, есть ли автомат, совпадают ли часы. Это единственный способ узнать реальную точность выборки. Без этой цифры ты не знаешь, что выпускаешь.

**3. Кабинет для магазина.** Даёт то, чего нет ни в одном открытом источнике — статус конкретного автомата от того, кто стоит рядом с ним.

**4. TOMRA Status API.** Долгий путь, но там настоящая телеметрия. Регистрация в Developer Portal самообслуживаемая.

## Честная оценка, где ты сейчас

Дизайн готов. Архитектура и защита готовы. Данные — сырые, и это единственное, что отделяет приложение от продакшена. После `import:shops` ты увидишь настоящие названия и тысячи точек, но их достоверность будет неизвестна до первой проверки ногами.

Не выпускай публично до этой проверки. Приложение отвечает на один вопрос, и если оно врёт, второго шанса у него не будет.
